# Tennis Data Explorer: Member 4 Database Integration (v2)

## Purpose

This folder contains the unified SQL Server integration for the six datasets delivered by M1, M2 and M3. It creates one `tennis_db` schema, loads all CSV files in a single transaction, and provides validation and analysis scripts for the rest of the project.

## Compatibility

- Microsoft SQL Server 2017 or later, tested with SQL Server 2022
- Microsoft ODBC Driver 18 for SQL Server
- Python 3.10 or later
- `pyodbc` and `python-dotenv`

## Included files

- `sql/schema.sql`: unified six-table SQL Server schema with keys, foreign keys and indexes.
- `sql/queries.sql`: M1 Q1 to Q7, M2 Q2.1 to Q2.7, and M3 Q1 to Q10.
- `sql/checks.sql`: post-load row counts and integrity checks.
- `database/connection.py`: reusable SQL Server connection helper.
- `database/load_data.py`: CSV validation and atomic six-table load.
- `database/validate.py`: offline CSV preflight and live database checks.
- `data/`: the six delivered CSV datasets and `preload_validation_report.json`.
- `requirements.txt` and `.env.example`.

## Setup

```bash
python -m venv .venv
# Windows PowerShell: .venv\Scripts\Activate.ps1
# Linux or macOS: source .venv/bin/activate
pip install -r requirements.txt
```

Copy `.env.example` to `.env` and set `DB_SERVER`, `DB_PORT`, `DB_NAME`, `DB_USER` and `DB_PASSWORD`. For Windows integrated authentication, set `DB_INTEGRATED_SECURITY=yes` and leave the user and password empty. Do not commit `.env`.

## Commands

Run these commands from this folder.

Validate the CSV files without a database:

```bash
python -m database.load_data --validate-only --csv-dir data
```

Initialize the schema and load all six tables:

```bash
python -m database.load_data --init-schema --csv-dir data
```

Validate the loaded database:

```bash
python -m database.validate --db --csv-dir data
```

The `--init-schema` option initializes the schema and then loads the data. To create the schema only, run `sql/schema.sql` in SSMS.

## Loader behavior

The loader checks all six files before changing the database. It then replaces all six tables inside one transaction. Competition self-references are cleared before deletion and valid parent links are restored after insertion. Any failure rolls the transaction back. The `rank_id` column is generated by SQL Server and is not present in the rankings CSV.

## Data handling notes

- M1 reports 3024 distinct parent IDs that are absent from the competition extract. The schema keeps a nullable self-referencing `parent_id`. The loader nulls unavailable parent links and reports how many rows changed. Valid parent links are restored after all competitions are inserted.
- M2 allows `venues.complex_id` to be NULL. This package keeps it nullable.
- M3 uses `rank_id` as the ranking table primary key. Shared rank and points values between doubles partners are legitimate and are not treated as duplicate ranks.
- The M3 CSV does not contain tour, gender, year or week columns. Its ATP and WTA rankings are therefore combined in the delivered queries. Points from different tours are not directly comparable.

## Member 5 handoff

`get_connection()` returns a pyodbc connection that can be used with pandas:

```python
from contextlib import closing
import pandas as pd
from database.connection import get_connection

with closing(get_connection()) as conn:
    df = pd.read_sql_query(
        """SELECT c.name, c.country, r.[rank], r.points
           FROM dbo.competitors c
           JOIN dbo.competitor_rankings r
             ON r.competitor_id = c.competitor_id
           ORDER BY r.[rank], r.points DESC""",
        conn,
    )
```

Use parameterized SQL for user-entered filters.
